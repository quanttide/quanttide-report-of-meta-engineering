# 复盘报告：人类 / 智能体 / 规则引擎的分工

> 场景：为一份「认知地图」profile 索引构建形式化推理工具，并借一次真实的
> 「放假心里封闭，不知道怎么办」问询，完整跑通了三方协作。
> 本报告归纳三者**各自不可替代的职责、能力边界与失败模式**，以及由此
> 暴露出的关键风险。

---

## 1. 角色一览

| 角色 | 在本次任务中的职责 | 能力边界 | 典型失败模式 |
|---|---|---|---|
| **人类**（你） | 提供原始 profile 文本；提出真实问询；**确认语义是否正确**；最终拍板是否采纳 | 不掌握图结构与查询语法；不在场时无法持续运作 | 把形式化输出误当作"已验证的结论" |
| **智能体**（我） | **语义映射**：将自然语言归因到图节点；**创造/扩充节点**；做判断性解读；把口语转成结构化 YAML | 判断可能错；没有"真值"来源；不强制校验正确性 | 入口选错、节点造错，且输出显得自信 |
| **规则引擎**（代码） | **关系代数**：沿已存在的边做精确查询；**签名约束**：校验端点类型；**固化**：把结论写成可复现的结构 | 不检验映射正确性；不自动寻路；不接管语义 | 对错误入口忠实地输出"看起来合理"的完整链 |

**一句话**：人类给语境与裁定权，智能体做判断与翻译，规则引擎做约束与固化。
三者的权力不重叠——这正是协作能成立的前提。

---

## 2. 一次完整协作的时序（标注"谁在做"）

```
① 人类：「放假没出去玩，心里封闭，怎么办？」
        └─ 提供真实语境（只有人类能给出）

② 智能体：把"封闭"归因到情绪「疏离」
          （判断：与「不想看自己写的内容」同源，二者均 evokes→疏离）
        └─ 这一步在代码之外，纯语义映射，无结构参与

③ 规则引擎：cmap out / chain 沿边查询
          「疏离感的封闭 → 疏离 → 修剪上下文 → 与自己保持连接 → 消耗型活动」
        └─ 只负责"沿着真实存在的边走"，不评价入口对不对

④ 人类：「这个归因合理」→ 授权更新
        └─ 语义正确性的唯一裁定者（主观确认，非代码验证）

⑤ 智能体：写入 YAML（新增节点 + 补断链 + 修孤立节点），每条标 inference
        └─ 把判断固化进结构，使其可复查

⑥ 规则引擎：cmap validate → 0 错误 0 孤立
          （途中抓出智能体写错的 6 条签名非法边）
        └─ 纪律在此生效：约束创造，而非替代创造

⑦ 复盘：人类要求解释"为什么会匹配到疏离"
        └─ 智能体指出：匹配是智能体做的，引擎无语义匹配能力
```

---

## 3. 各方的"不可替代"与"不可靠"

**人类不可替代**：你是唯一能确认语义正确性的一方。代码验证的是"边连得对不对"，
你验证的是"这条线该不该连"。前者可自动化，后者不行——它依赖你对自身状态的真实感知。

**人类不可靠处**：当结论被包装成结构化、完整的四段链时，容易默认它"已被验证"。
形式化是双刃剑，详见第 4 节。

**智能体不可替代**：语义映射与节点创造无法由规则引擎完成——图里没有的词，
代码无从匹配。把"封闭"接到「疏离」、并由此新建「与自己保持连接」作为价值锚点，
是判断性工作，不是检索。

**智能体不可靠处**：判断可能错。且因为输出以权威口吻呈现，错误会被放大。

**规则引擎不可替代**：约束与固化。它保证(a)只走真实存在的边、(b)端点类型合规、
(c)断链时明说"无"而非硬凑、(d)结论可复现可争议。没有它，对话说完即散。

**规则引擎不可靠处**：**不检验入口正确性**。这是设计使然，也是最大盲区。

## 4. 关键风险：形式化的"权威幻觉"

为验证风险，做了一组对照实验——把"封闭"**错归**到不同触发点，观察引擎反应：

| 假设的（错误）入口 | 引擎输出 |
|---|---|
| 范围失控 | 规模焦虑 → 缩小窗口/去建设平台 → 积累感 → 消耗型活动 |
| 战略失败 | 信心的底色 → 回到虚构世界 → 与自己保持连接 → 消耗型活动 |
| 进度停滞 | 高压与喘息 → 补觉与放手 →（断） |

**结论**：引擎对错误入口**毫无抗议**，照样输出结构完整、逻辑自洽、终点一致的链。
输出越结构化、越完整，就越"像答案"。一个错误的归因，会被包装成一条无可辩驳的推理。

> **这正是最该警惕的地方**：规则引擎的"不会编造连接"是优点，
> 但它同样"不会质疑入口"。纪律保证错误**可见**，前提是有人去看——
> 而形式化外观恰恰会让人**不去看**。

**缓解手段**（已在实现中落地）：
- 所有智能体的推断边标注 `inference: inferred` + `note`，与原档事实（无该字段）分离；
- `validate` 持续可跑，把结构错误挡在门外；
- 工具定位为"提问的起点"而非"答案的终点"。

---

## 5. 设计取舍：为什么是"最小可用"

- **不做自动多跳寻路**：`chain` 只按 `evokes→responds_to→serves→excludes`
  逐段推进，段间不自动跳转。宁可暴露断链，也不替用户脑补连接。
- **不接入语义匹配**：查询要求精确节点名，避免"看起来匹配"的幻觉。
- **不接管判断**：引擎永远在"执行"层，不在"决策"层。

这三个"不"，共同指向一个原则：**让判断留在人类/智能体一侧，让纪律留在规则一侧。**

---

## 6. 给未来的三条纪律

1. **凡是智能体写入的边，都要能溯因。** 没有 `inference` 标注的推断，视为待核。
2. **形式化输出默认"未验证"。** 结构化 ≠ 正确；看到完整链先问"入口是谁选的"。
3. **引擎是镜子不是脑子。** 它忠实地反映你（或智能体）给它的入口，
   它的可信度上限 = 入口判断的可信度。
