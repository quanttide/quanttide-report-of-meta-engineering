# 人机分工复盘：人类、智能体、规则引擎各管哪一段

读这类复盘的人只想知道两件事：上次错在哪、下次开工照哪几条办。2026-10-05，为一套「认知地图」档案索引做形式化推理工具——把用自然语言写的自我认知档案转成可查询的关系图——借一次真实的「放假在家心里封闭，不知道怎么办」问询，把三方协作完整跑了一遍。**这次留下的是一条边界：人类给语境与裁定，智能体做语义映射与判断，规则引擎做约束与固化，三方的权力不重叠；要防的是形式化外观把没验证过的判断包装成结论。**

## 一、一次问询怎么走完

```text
① 人类：提出真实问询「放假没出去玩，心里封闭，怎么办？」——只有人类能给出这个语境
② 智能体：把「封闭」归因到情绪「疏离」（判断它与「不想看自己写的内容」同源）——纯语义映射，结构不参与
③ 规则引擎：cmap out / chain 沿边查询——疏离 → 修剪上下文 → 与自己保持连接 → 消耗型活动
④ 人类：确认「这个归因合理」并授权更新——语义正确性的唯一裁定
⑤ 智能体：写入 YAML，新增节点、补断链、修孤立节点，每条标 inference——把判断固化成可复查的结构
⑥ 规则引擎：cmap validate 通过，0 错误 0 孤立，途中抓出 6 条签名非法边
⑦ 复盘：人类问「为什么会匹配到疏离」，答案是匹配由智能体做，引擎没有语义匹配能力
```

这条链里每一步都只能由一方完成：语境只有人类能提供，语义归因只有智能体能做，沿边查询与校验只有代码能做，而那条边该不该连，最后要人类点头。

## 二、三方各自不可替代在哪，不可靠在哪

人类不可替代，是因为语义正确性没有代码可验证的判据。「边连得对不对」可以自动查，「这条线该不该连」只能靠人对自身状态的真实感知。人类不可靠的地方也在这里：结论一旦被包装成结构完整的四段链，容易被默认成「已经验证过」。

智能体不可替代，是因为图里没有的词代码无从匹配。「封闭」接到「疏离」、并由此新建「与自己保持连接」作为价值锚点，是判断不是检索。它的不可靠同样明显：判断可能错，而输出用的是权威口吻，错误会被放大。

规则引擎不可替代，是它保证了四件事——只走真实存在的边、端点类型合规、断链时明说无而不是硬凑、结论可复现可争议。没有它，对话说完即散。它的盲区是设计使然：不检验入口选得对不对。

## 三、风险：形式化的权威幻觉

为了看清这个盲区，把「封闭」分别错归到另外三个候选触发点（范围失控、战略失败、进度停滞）重跑一遍。引擎三次都照常输出结构完整、逻辑自洽的链：错归到范围失控走「规模焦虑 → 缩小窗口/去建设平台 → 积累感 → 消耗型活动」，错归到战略失败走「信心的底色 → 回到虚构世界 → 与自己保持连接 → 消耗型活动」，错归到进度停滞走到「高压与喘息 → 补觉与放手」后断掉。三次都没有任何抗议。

引擎不会编造连接，这是优点；它同样不会质疑入口，链路越是完整就越像答案。一个错的归因会被包装成一条无可辩驳的推理，而形式化外观恰恰让人不再去看。

实现里已经落地了三条缓解：智能体的推断边标 `inference: inferred` 并附 `note`，与原档事实（不带该字段）分开存放；`cmap validate` 随时可跑，把结构错误挡在门外；工具定位成提问的起点，不是答案的终点。

## 四、设计上三个不做

`chain` 只按 `evokes → responds_to → serves → excludes` 逐段推进，段间不自动跳转，宁可暴露断链也不替用户脑补连接；查询要求精确节点名，不接语义匹配，避免「看起来匹配」的幻觉；引擎永远停在执行层，不接管决策层。三个不做指向同一句：判断留在人类与智能体一侧，纪律留在规则一侧。

## 五、下次开工的三条

1. 智能体写入的边都要能溯因，没有 `inference` 标注的推断一律视为待核；
2. 形式化输出默认未验证，看到完整链先问一句入口是谁选的；
3. 引擎是镜子不是脑子，它的可信度上限等于入口判断的可信度。

## 六、边界与落地

边界：这套分工结论出自一次问询、一份档案，样本只有一例；第三节的三个错误入口是事后补跑的对照，用的是同一个正确归因的三种错挂法，不是一个独立样本；四段链的口径只在这份档案上验证过，换一份档案要先复跑 `cmap validate`。不适用的是把这条边界当成对规则引擎的贬低——它不质疑入口，是因为它只该管执行，质疑入口本来就是人类那一侧的动作。

落地：三条纪律从下次开工起适用，机器那一侧已经写进工具用法（`inference` 标注、`validate` 门禁、命令定位在执行层），人类那一侧要守住的动作只有一个——看到完整链先问入口。
